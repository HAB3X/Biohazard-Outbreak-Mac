# Outbreak Studio: what you can do

**Build** (the first view) is the running game, live: the game is started behind the scenes, its pictures stream into the page about fifteen times a second, and the free camera you fly (W A S D, right-drag) is the game's camera, so you see the room as the player does while you move through it (the first start takes about a minute; the Brighten button lifts the game's dark pictures). Your changes reach the running game by loading the room again: moves, hides, turns and resizes in about twenty seconds; new objects and new rules grow the room's files, which restarts the game (about a minute). It is the whole editor in one place: fly with W A S D and right-drag, click anything to pick it, drag it (arrows slide it along x or z, the green arrow lifts, the ring turns, the diamond resizes; Ctrl+D copies, Del removes), and put props down from the **Library** (B) or the **Add** menu. Over the game's own picture your changes show as sketches until the picture is made again (about a minute after you stop). **Rooms** (top left) and **This room** (rules, clearing the room) open the side lists, which stay out of the way until asked for. **Camera views** is the old per-camera view, **Plan** is from above. The **?** button repeats the tour; the arrow beside undo lists every step.

Start it with `./studio.sh` (File 2, scenario 40 opens first; the scenario menu at the top switches). Everything is picked up and dropped in one picture. **Game view** (the default) shows the room exactly as the player sees it: through the room's own fixed cameras, with the game's baked light (step through a room's cameras with the arrows, or `,` and `.`; picking something switches to a camera that shows it). Everything you see is Studio's own live 3D drawing of the game's models, lit as the game lights them; no pictures or video of the game are ever shown in place of it (the game runs only when you press Play or Test). **Plan** (from above) and **3D** (free orbit) are for overview and awkward spots.

Everything is undoable (⌘Z) and saved as you go (`work/studio/`).

## The game's pictures

Studio keeps a copy of the game running behind the scenes and photographs every camera of every room it can reach, one scenario after another (File 1's first, then File 2's 15, 20, 26 and 40), into `work/studio/survey/`. The chip at the top shows how far it has got. A room's pictures appear in Game view as they are taken. In File 1's first scenario only the bar and the next three rooms can be reached from the start (the doors beyond don't open without the story), so the rest show Studio's own, rougher drawing. In File 2 a room the doors don't reach is photographed by starting a game in it.

## What it can't do yet (measured, not guessed)

- **Pictures are the room's own pictures repainted** (the same size and number of colours), not new ones added; the pictures of a room are mostly atlases.
- **Start room** only where the scenario's event file has the opening start records (File 2's scenarios 15, 20, 21, 22, 23, 26, 27, 29, 30 and 40; File 1's start isn't in them, so File 1 has no start choice).
- **New room numbers**: a room can be cleared and built in, but a room with a number the scenario does not have is not built (the game stores its room index ahead of the room data).
